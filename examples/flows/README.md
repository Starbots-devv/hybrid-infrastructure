# Three synthetic infrastructure decisions

These are fictional, nominal-USD examples. Every price, arrival rate, service time, capacity observation and feasibility claim is a synthetic modeling input, not a provider quote or a production measurement. Each directory contains a closed, hash-bound input bundle (`schema_version` 1.1.0), explicit FinOps plans and a complete CLI-generated report with JSON, Markdown, HTML, CSV, diagrams, and both executive and implementation readings. The comparison series has 36 monthly points for both cash and allocated TCO.

| Flow | Current / month | Proposed cash / month | Proposed TCO / month | Incremental transition | Net cash at 12 / 36 months | Result under the example assumptions |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| [01 — hybrid workers](flow-01/bundle.json) | 720 | 500 | 540 | 1,200 | 1,440 / 6,720 | Hybrid conditionally recommended; local-only fails mandatory constraints |
| [02 — hidden costs](flow-02/bundle.json) | 520 | 620 | 620 | 400 | -1,600 / -4,000 | Stay with the current SaaS/API and managed database |
| [03 — stay managed](flow-03/bundle.json) | 260 | 305 | 305 | 600 | -1,140 / -2,220 | Stay with the managed application |

Flow 01 recovers its transition cost in month 6 on cash and month 7 on allocated TCO; its TCO net is USD 960 / 5,280 at 12 / 36 months. The USD 40 monthly ownership allocation is not a second cash purchase. In flow 02, an incomplete USD 290 quote becomes USD 620 once transfer (110), operations (80), power and replacement (65) and cloud fallback (75) are included. In flow 03, the VM costs 120 plus 60 for backup, network and security and 125 for operations each month; the 600 transition is never recovered within 36 months.

Open [flow-01/report/dossier.html](flow-01/report/dossier.html), [flow-02/report/dossier.html](flow-02/report/dossier.html) or [flow-03/report/dossier.html](flow-03/report/dossier.html) for the human-readable reports. The adjacent `evaluation.json` holds the exact series and constraints, and `artifact-manifest.json` records every report file hash. `subject.json` and `subject-manifest.json` bind the original input bytes so an independent security review can target the exact proposal. The reports stay `CONDITIONAL` because security is UNKNOWN, and all of them deny execution eligibility.

From the repository root, with the package installed, using the fixed example time:

```powershell
.venv/Scripts/sb-hybrid.exe validate --bundle examples/flows/flow-01/bundle.json
.venv/Scripts/sb-hybrid.exe analyze --bundle examples/flows/flow-01/bundle.json --as-of 2026-10-17T00:00:00Z --output-dir .local-output/flow-01-reproduction
.venv/Scripts/python.exe -m unittest discover -s tests/integration -p test_examples.py -v
```

Use a new output directory for each run. The inputs expire at `2026-11-01T00:00:00Z` by design. `build_examples.py` regenerates these inputs from `examples/hybrid-saving`; editing and resealing a copy changes its subject, so regenerate the report (and any security review) afterwards. The example reports were generated by the CLI at the fixed example time, without any provider API or credentials.
